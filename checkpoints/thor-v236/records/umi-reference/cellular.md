# Cellular notes from HakiOS (Xiaomi Mi 10 "umi", XNU 8796 / iOS 16.5) for Thor

Read-only survey of `reference-umi/hakios-xnu-kernel-umi-fixes`. `D/` = `devices/xiaomi-mi-10/overlays/xnu/files/bsd/dev/` (`umi_modem.c`, `umi_modem_mhi.inc` = `mhi.inc`, `umi_modem_qmi.h` = `qmi.h`, `data.inc`, `net.inc`, `pcie.inc`, `dma.inc`, `power.inc`, `coachz_bb_*.h`); `BB` = `devices/xiaomi-mi-10/drivers/umi/hakios.umi_baseband.cpp`; `MM`/`CELL` = `drivers/modem/hakios.mpss.c` / `hakios.cell.c` (generic, non-umi); docs in `devices/xiaomi-mi-10/`: `MD` MODEM-MAINLINE, `CC` COMMCENTER-umi, `CCA` COMMCENTER-ACTIVATION-umi, `VOLTE`, `NOTIF`, `SBS` STATUSBAR-SIGNAL-umi, `SBX` SANDBOX-umi. **[inferred]** = concluded, not read. `FLASH-umi.md` is absent.

## Summary
- umi's modem is an **external SDX55 on PCIe2** (17cb:0306); integrated MPSS is disabled (`MD:58,70`, `umi_modem.c:351`). umi's PCIe/BHI/Sahara loader does not apply to Thor. What transfers is the **CommCenter bridge** (`BB` + `coachz_bb_*.h`): transport-agnostic, written for an integrated modem started by "MBA/PIL code" (`coachz_bb_control.h:2,8-10`), plus `MM` as a reference for Thor's loader.
- **[inferred]** Thor's `pong-baseband/PongBasebandService.cpp` is a sibling port of the same headers (header only read). HakiOS adds the pending-request table, client pooling, endpoint insertion, DMS-reset rewrite, synthetic WDS indications, activation TLV 0x15, route-B IMS, cellinfo/GNSS clients.
- Works: LTE registration, carrier/bars, IPv4 data through CommCenter, MT SMS stored (`CC:535`, `NOTIF:9`, `VOLTE:172`). Not: calls, SMS banner/sound, stable HOME signal glyph, IPv6.

## Modem paths
1. `umi_modem=1` (kernel dial): own UIM/DMS/NAS clients, then WDA/WDS on `cmnet` to `pdp_ip0` (`data.inc:94-126`). No CommCenter, `default_route=manual`, so iOS apps do not use it (`MD:16,121`).
2. `umi_modem=2` (bridge): CommCenter dials; the kernel keeps boot, QRTR, servreg, TFTP, EFS and the QMAP pump (`BB:3-12`, `mhi.inc:18-19`). The loader emits `/baseband` (`baseband,n41`, `class=3`, 40-byte `config`) and `/product/baseband-chipset=mav17` only here (`CC:265,373,456-461`).
3. Generic integrated MPSS (`MM:1-60`, SM7325): `modem.mdt`+`modem.b00-29` (85 MB) into 246 MB at 0x8b800000 via TrustZone PAS image 4; SMP2P items 435/428/421; GLINK `IPCRTR`; QRTR; DMS online; NAS poll; RMTFS; TFTP; IPA to `en1`. Never reaches CommCenter (`MD:138-140`). **Thor needs 3's boot plus 2's bridge.**
4. IMS owners: `ims-on` (Apple AP SIP) vs `modem-ims` ("route B", `/var/db/hakios-voice/modem-ims`) (`umi_ims.inc:12-14`).

## Boot and firmware
External X55:
- Power is firmware-established (no PMIC PON or soft-reset GPIO) and EE must be PBL 0: no cold reset (`MD:66`, `umi_modem.c:275-277`). TLMM 0x0f500000+pin*0x1000: PERST 85, AP_STATUS 56, AP_ERRFATAL 57 out; MDM_STATUS 3, MDM_ERRFATAL 1, CLKREQ 86, WAKE 87 in; RPMh `ldoa5` 880 mV, `ldoa9` 1200 mV (`pcie.inc:53-66`, `power.inc:9-10`). PCIe2: GCC 0x00100000, PARF 0x01c10000, PHY 0x01c16000, DBI 0x64000000, CFG 0x64100000, BAR0 0x64300000, SMMU 0x15000000 (private context, SID 0x1d01), 16 MiB pool at IOVA 0xb0000000; MSI masked, rings polled (`umi_modem.c:47-57`, `dma.inc:79-96,175,191-232`).
- Load: BHI takes `sbl1.mbn` (548,056 B, id 21); MHI with 6 event rings (64/128/64/64/1024/2048 TREs); Sahara on channels 2/3: HELLO 1, READ_DATA 3/0x12, END_IMAGE_TX 4, DONE 5, DONE_RESP 6. 17 images from `/fw/sdx55/sahara.map` or the Android `modem` FAT (`image/sdx55m/*`); ids 16/17/20 (`mdm1m9kefs1/2/3`, 8 MiB) and 34 (`mdmddr`, 1 MiB) are read-only UFS (`mhi.inc:44,340,437-446,552-557,614-658,1140-1154`).
- Channels: IPCR 20/21 (ER0), EFS 10/11 (ER1), IP_HW0 100/101 (ER4/5), DIAG 4/5, QMI_WWAN 14/15 unused (`MD:113-122`).
- QRTR: v1 (32 B) and v3 (16 B) headers; host node 1; NEW_SERVER/DEL_SERVER go to the bridge. Host services: servreg locator 64 (GET_DOMAIN_LIST 0x21) on 0x4001; TFTP 4096 v1/v3 on 0x4002/0x4003, published only once EFS service 21 appears; `/readonly/firmware/image/X` maps to FAT `image/X`; writes acked and dropped (`mhi.inc:665-694,845-942`).
- EFS on X55: **no rmtfs**. Initial EFS is the Sahara images; the mission-mode sync on 10/11 is Sahara memory-debug (read-and-discard, RESET 7, RESET_RESP 8), RAM only (`mhi.inc:943-1014`). So nothing CommCenter sends (PDC, NV) persists (`CC:236-239`).

Integrated modem (`MM`): RMTFS service 14 (OPEN 1, CLOSE 2, RW_IOVEC 3, ALLOC_BUFF 4, GET_DEV_ERROR 5); 2.5 MB buffer below 4 GB (default 0x9c700000, `modem_buffer=`) shared through `SCM_MP_ASSIGN` with VMIDs HLOS 3, MSS_MSA 15, NAV 0x2b; `modemst1`, `modemst2`, `fsc`, `fsg` read from UFS into RAM, writes stay in RAM (`MM:3548-3578,3629-3652,3659-3706`). **[inferred]** Thor's "read-only rmtfs" mirrors this.

BBUpdater decoy: Apple's `Mav17-*.Release.bbfw` (62 MB) at `/private/preboot/<boot-manifest-hash>/usr/local/standalone/firmware/Baseband/Mav17` (`CC:452-455`, `build.sh:729-741`); BHI reads return a serial, chip id 0x0003b0e1 and the default unfused PK hash; the Sahara device end asks for image 0x15 and drops the bytes (`coachz_bb_sahara.h:40,94-106`, `BB:69-70,893-899`).

## QMI services/messages used
QMUX on qmux1/qmux2; the SDU minus its 6-byte header is QMI over QRTR. CTL (0) is answered locally: GetVersionInfo 0x21, GetClientId 0x22, ReleaseClientId 0x23, Sync 0x27. One client id = one QRTR port 0x4100+slot; 96 slots, pooled, never deleted (`coachz_bb_qmux.h:8-16,41-45,58-59,134-169`).

| Service | Messages and TLVs | Where |
|---|---|---|
| UIM 0x0b | Get Card Status 0x2f (wait for app state 7); Read Transparent 0x20 of EF_ICCID 0x2fe2 / EF_IMSI 0x6f07 (TLV 0x02, 0x11), sniffed | `qmi.h:40-43`, `coachz_bb_data.h:363-412` |
| DMS 0x02 | Get/Set Operating Mode 0x2d/0x2e (TLV 0x01); online retried while error 52; ABM's mode 4/5 rewritten to 1 | `qmi.h:58-67`, `umi_bb_pending.h:79-96` |
| NAS 0x03 | Get Serving System 0x24 (TLV 1), Get System Info 0x4d, Initiate Register 0x22, Set System Selection Preference 0x33 (TLV 0x23); indications 0x24/0x4e forwarded; Apple 0x555b acked locally; Apple 0x5556 answered from Get Cell Location 0x0043 | `qmi.h:44-57,147-158`, `umi_cellinfo_qmi.h:10-14` |
| WDA 0x1a | Set Data Format 0x20: 0x11 LLP 2 (raw IP), 0x12/0x13 DAP 5 (QMAP), 0x15 32 datagrams, 0x16 32768, 0x17 endpoint {3,4} | `qmi.h:79-92`, `coachz_bb_data.h:25-38` |
| WDS 0x01 | Bind Mux Data Port 0xa2 (0x10 endpoint, 0x11 mux), Set IP Family 0x4d, Start 0x20 (0x19 family, 0x14 APN), Stop 0x21, Packet Service Status 0x22, Get Runtime Settings 0x2d (0x1e IPv4, 0x20 gw, 0x21 mask, 0x15/0x16 DNS, 0x29 MTU, 0x25 IPv6+prefix); call-end 0x10/0x11 | `coachz_bb_pdp.h:10-14`, `qmi.h:93-112,160-177` |
| QOS 0x04 | Bind Data Port 0x2b (endpoint inserted) | `coachz_bb_data.h:30,97-105` |
| BSP 0xe2 (Apple) | ActivationRegister 0xb00c, indication TLVs 0x01=0, 0x4f/0x50=2, 0x56/0x57=1, 0x15=1, 0x42 ICCID, 0x43 IMSI; ChipInfo 0xb001; SendFile 0xa000 (ack TLV 0x40 next segment, indication 0xa001); SetConfig 0xe00d | `coachz_bb_data.h:276-339`, `BB:376-467` |

Bridge-owned clients on own QRTR ports: cell info NAS 0x0043 (0x4201); IMSA 0x21 Bind Subscription 0x33, Get Registration 0x20, indications 0x22-0x24 (0x4203); IMSS 0x12 preamble 0x98/0x1e/0x1f/0x2a/0x90/0x48 then Set Enabled 0x8f (0x4204); IMSDCM 770 (0x4205) (`umi_ims_protocol.h:17-81`). No kernel-side NAS event registration exists: CommCenter's register requests are forwarded and the dial path only polls.

## Data networking
- Port: MHI IP_HW0, raw IP over basic QMAP (5), no checksum, downlink aggregate up to 32768 (`data.inc:7-57`, `qmi.h:178-186`). No NCM or MBIM.
- Interfaces: `pdp_ip0..3` = QMAP mux 1..4, `IFNET_FAMILY_CELLULAR`, `IFT_CELLULAR`, point-to-point, `IFNET_INIT_LEGACY|IFNET_INIT_NX_NOAUTO`, PF_INET/PF_INET6 plumbers (`BB:1161-1291`). `IFF_RUNNING` follows the WDS state per mux and the WDA format (`BB:1293-1317`).
- **CommCenter owns WDS and addresses**: the bridge only watches bind/start/stop/status for the mux-to-family map (`BB:325-351`). IP configuration is static from WDS runtime settings, applied by CommCenter; address ioctls are handed to XNU's `in_control`/`in6_control` (`BB:1197-1231`). Routes and DNS come from CommCenter's IP service through configd; the kernel installs nothing.
- What makes Safari work: a connected data context (WDS 0x20 ok, 0x22, runtime settings), the activation gates passed (CCA gates 10, 14), and `pdp_ip0` RUNNING with IPv4. Evidence is packet counters (tx 867 / rx 1079 in 91 s, `CC:535`) and later docs treating "LTE data" as a working baseline (`VOLTE:172`). An explicit Safari-over-cellular confirmation was **not found**; it is the listed acceptance check (`CC:282`).
- The generic integrated path fakes Ethernet instead: `en1` with in-kernel ARP and DHCP carrying the WDS settings (/24, router .1) so configd treats it as a USB adapter; IPv6 not carried (`CELL:1-18,82-223,309-342`). The `umi_modem=1` path sets a static address from WDS with no route or DNS (`net.inc:105-132`).

## CommCenter
- Job: cellular `com.apple.CommCenter` ships, `-noncellular` is denied, `_LimitLoadToDeviceTree=baseband` is kept (`mkjobs.py:226,314-316`, `build.sh:131-133`). Without the bridge it crash-looped on "Could not find AppleIPAppender service" and "Unable to communicate with AppleBaseband driver" (`CC:53-58`).
- Published IOKit classes (user-client class names must match CommCenter's sandbox): `AppleBaseband` (named `baseband`, DT properties copied, accepts StartDevice/StopDevice), `AppleBasebandPCIControl`, one `AppleBasebandPCIInterface` per channel (18, pbl/sahara/qmux1/qmux2 included; selectors 0-12), `AppleBasebandPCIMAVPDPManager`, `AppleIPAppender` (selector 16 blocks PDP traffic, rest zero-filled) (`coachz_bb_channels.h:20-51`, `BB:994-1047,1381-1439,1443-1518`).
- Board selectors (reset, power, mux, VBUS, state) are recorded only; GET_* report not-in-reset and powered (`coachz_bb_control.h:23-91`). A reset frees ABM's clients and stops its calls without touching the modem (`BB:1054-1070,1091-1115`).
- Activation: 16.5 has the postponement-ticket gate; Internet is rejected when `!ticket && activationEnabled` (`CCA:5,82-116`). No-patch route: BSP indication TLV `0x15=1` (kDisabled) in every indication (`CCA:119-156`, `coachz_bb_data.h:271-300`). Device activation is faked by a mobileactivationd hook returning `Activated` (`CCA:162`).
- Carrier bundle: CommCenter pushes Mav files through BSP 0xa000; each segment is acked with the next segment number and the file ends with indication 0xa001, else it resets the baseband every ~12 s (`coachz_bb_data.h:302-339`). BBUpdater insists on the personalized preboot path (`CC:434-448`); MobileGestalt `HasBaseband` can stay false from the `/var` cache (`CC:467-468`).

## SMS
- No WMS code: WMS (0x05) requests and indications are forwarded byte for byte (`CC:313`, `BB:521-576`). MT path from logs: CommCenter decodes the PDU, imagent `kSmsRetrieveMessage`, `IMDPersistenceAgent` (IMDNotificationsController), Messages (`NOTIF:43-49`). Sending is not documented as tested on HakiOS; only the Linux reference reports send/receive (`MD:62`). **[inferred]** MO SMS relies on the same forwarding.
- Required fix: `MessagesBlastDoorService` died with SIGTRAP because `sandbox_check(self)` was 0; the Sandbox stand-in (`kern_minimac.c`, otherwise AMFI/Sandbox only) now reports sandboxed processes truthfully (`SBX:5-37`, `CC:598-601`).
- Open: no banner or sound. The SMS is stored but never submitted to SpringBoard's notification server; suspects are the `_haveMigrated` check and the vanishing RemoteManagement store (`NOTIF:142-160,213-225`). `inject_notifications.m` is diagnostics only; every hook calls through (`NOTIF:229-251`). IMS SMS: not found.

## IMS/VoLTE
- The "IMS bridge" is `umi_ims.inc`, default off. `ims-on` keeps Apple's SIP stack (IPTelephony) as registration owner, forces the IMS bearer to IPv6, runs the address ioctls, and synthesizes Apple's private WDS **0x5561 "DAD complete"** indication (TLV 0x01 = 17-byte IPv6 address and prefix) about 1 s after the 0x2d reply, else CommCenter reports `kDADMissing` (`VOLTE:294-337`, `umi_ims_protocol.h:10-22`). `modem-ims` instead enables the X55's own IMS (IMSS 0x12, IMSA audit) and gates Apple's Start on the modem being unregistered (`umi_ims.inc:43-70`).
- `umi_vops=1` rewrites NAS 0x4e/0x4d TLV 0x21 (LTE VoPS) to 1 so CommCenter allows IMS voice (`BB:137-171`).
- Works: the IMS IPv6 bearer starts (mux 2, APN `IMS`). Not: no SIP registration, no call. Media is blocked because the X55 publishes no RTP 0x28 endpoint (allocation error 31), AUDIO 0xe1 and ELQM 0xe7 go unanswered, and IMSA falls silent while the PCIe function leaves the bus mid-attempt (`VOLTE:80-86,200-215`, `BB:1771-1781`). CS dial ends in `NO_NETWORK_FOUND` (`VOICE-CS-umi.md:3`).

## Status bar
Native path: CommCenter, CoreTelephony, `STTelephonyStateProvider` (inside SpringBoard), `SBStatusBarStateAggregator` item 4, `UIStatusBar_Modern`. The old `inject_sb.c:520-703` hooks fed by `kern.hakios.cellular_*` sysctls are off by default (`/var/umi-statusbar-signal.legacy` restores them) and carry a latent wrong-arity bars setter (`SBS:209,273-275`). `umi_statusbar_signal.h` is observation only, enabled by `/var/umi-statusbar-signal.trace` (`umi_statusbar_signal.h:1-12`, `SBS:279-283`). Open: the HOME glyph vanishes after Control Center; a placement/overflow decision, not missing data (`SBS:86-113`).

## Device-specific vs generic
- SM8250/Mi 10 only: every address above, the GPIO numbers, `ldoa5/ldoa9`, SID 0x1d01, the MSI alias, 17cb:0306, the SDX55 image names and Sahara ids, the `modem` FAT `image/sdx55m`, `cmnet`, Mav17 chip id 0x3b0e1 and firmware path (an iPadOS 18.7 identity differs).
- Generic: QMUX-to-QRTR bridging, CTL handling, the pending table, client pooling, endpoint insertion, DMS-reset rewrite, activation and carrier-file answers, WDS observation, `pdp_ip` ifnets, the QMAP v1 codec, TFTP and servreg hosts, EFS discard, bridge-owned IMS/GNSS/cellinfo clients.
- xnu-8796 KPIs used: `ifnet_allocate_extended`/`ifnet_init_eparams`/`IFNET_INIT_NX_NOAUTO`/`IFT_CELLULAR`, `proto_register_plumber`, `ml_io_map_unmappable`, `kmem_alloc_contig`, `IOMallocData`, `IOUserClient::externalMethod(IOExternalMethodArguments*)`, `sendAsyncResult64`, `kOSAsyncRef64Count`. **[inferred]** In Thor's tree (`thor-out/v231-unified/build-tree/.cache/xnu-work`) all are still declared (`bsd/net/kpi_interface.h`, `iokit/IOKit/IOUserClient.h:273`, `iokit/IOKit/OSMessageNotification.h:89`); xnu-11417 adds `IOUserClient2022` with `IOExternalMethodArgumentsOpaque` beside the old path (`IOUserClient.h:565-583`). The larger unknown is the iPadOS 18.7 userland ABI: channel table, BSP TLVs, whether the 0x15 route survives (on 17.7.11 the reference needed a CommCenter patch, `CCA:236-243`).

## Dead ends
- Bridge protocol traps, each with its fix: an unanswered request causes an `ATCS_TIMEOUT` reset loop every ~26 s (pending table, `CC:471-508`); ABM's DMS mode-4 reset made the X55 re-sync EFS and go silent (rewritten to low power, `CC:471-482`); DEL_CLIENT on release gave NAS `CLIENT_IDS_EXHAUSTED` (pool clients, `CC:546-557`); mux-only WDS/QOS bind gives `INVALID_ARG 0x30` (insert {3,4}, `CC:484-496`); a cross-service indication on a reused port crashed ABM (source-port check, `CC:549-560`); a 3GPP-refused Start made CommCenter wait 360 s then reset (synthetic 0x22, `CC:571-596`).
- Board traps: TFTP published before EFS service 21 leaves the radio offline (`MD:127-128`); bus mastering before an SMMU context, or MMIO through gated clocks, stalls the SoC, and gating GCC 0x8d058 hung Wi-Fi (`MD:78`, `umi_modem.c:162-173,198-202`); a link-fault restart hung the phone, so restart is default off (`umi_modem.c:66`); Wi-Fi's 19.2 MHz REFGEN vote broke PCIe2, which needs 100 MHz (`MD:153`).
- Kernel dial without CommCenter is unused by apps; ICMP to 1.1.1.1 failing was the carrier (`CC:400-402`).
- Still open: VoLTE media and the IMSA drop, HOME signal glyph, SMS banner/sound, IPv6, suspend/resume, no cold reset.
